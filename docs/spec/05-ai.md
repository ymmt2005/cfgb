# AI summaries and generated ownership

Only `cfgb summarize`/evaluation may call a model. The renderer and Worker do not.
Hatena inventory/plan/apply/mark-moved also make no model calls and require no AI
credentials. Translation-pair candidates use deterministic migration heuristics
and explicit human decisions; missing imported summaries are handled separately
by `cfgb summarize` during authoring.
Keep the Go domain interface independent of Cloudflare: input locale/title/body,
output plain summary plus provider/model/prompt metadata. The Cloudflare adapter
is v1's default; model choice remains an evaluation result, not a hard-coded name.

## Input and output hashes

Define `normalizeBody`: remove frontmatter and its closing delimiter/newline,
convert CRLF and lone CR to LF, remove trailing LF characters, append exactly one
LF. Do not trim other spaces or perform Unicode normalization. Title is the
parsed string with no implicit trim. Hash UTF-8 bytes:

```text
sourceHash = "sha256:" + hex(SHA256(
  "cfgb-summary-v1\n" + locale + "\n" + title + "\n" + normalizeBody(body)
))
outputHash = "sha256:" + hex(SHA256(UTF8(parsed summary string)))
```

Locale/title/body are the entire semantic summary input. Dates, slug, topics,
assets and existing summary are excluded, so changing URL metadata does not cause
unnecessary provider calls. `promptVersion` is recorded separately; a prompt or
model upgrade does not automatically overwrite existing generated text. Re-evaluate
first and explicitly select a refresh policy in a later tool release.

The sidecar groups generated records under `variants.<locale>.summary`. Import
provenance is also per variant, since each translation has a different source.
Human summaries need no record. Fixture records use `provider: fixture` and
`model: deterministic-fixture-v1` to make their synthetic origin explicit;
these identifiers are not selectable production adapters.

## State transitions (order is normative)

| Current state | Action |
| --- | --- |
| Summary absent/empty/whitespace-only | Generate, even if old ownership record exists |
| Summary present, no ownership record | Preserve as human-authored |
| Current output hash differs from recorded output hash | Preserve as human-edited; report protected |
| Output matches and current source hash equals record | No-op |
| Output matches and source hash differs | Regenerate |
| Explicit `--replace-manual` for one selected variant | Generate after showing selection in dry-run; no CI usage |

Missing-summary detection uses the same Unicode White_Space trimming rule as
validation. Non-string values are structural errors, not a generation request.
Do not generate from an empty/whitespace-only body.

A protected summary can remain intentionally short or stale; diagnostics invite
review but do not seize ownership. A summary manually edited then restored to the
exact generated bytes is considered generated again; this is a documented
limitation of content-hash ownership. Sidecar deletion opts into manual ownership.

Validate output before any mutation. Output is one plain paragraph, no Markdown,
HTML, links, invented claims or unsolicited judgments. Targets: Japanese 80–160
Unicode code points; English 25–50 whitespace-separated words after trimming and
collapsing whitespace. These counting definitions apply to deterministic checks;
human text outside the target is a warning, generated text must meet the target.
Do not truncate an overlong article input silently: fail with a selection/budget
diagnostic or use a separately evaluated chunking strategy in a future version.

Retry bounded transient 429/5xx/network errors, honoring Retry-After with jitter;
maximum three attempts and a 120-second per-article wall-clock budget. One repair
attempt for invalid summary output counts toward the same attempt limit. Never
fallback to another provider without explicit configuration. If all fail, write
neither frontmatter nor sidecar. Re-read file hashes before committing both outputs
to avoid overwriting a concurrent manual edit. Journal recovery must never mark
unwritten output as owned.

## Gateway and credentials

Use the documented Cloudflare OpenAI-compatible gateway endpoint built from
`CFGB_CF_ACCOUNT_ID` and `CFGB_CF_GATEWAY_ID`, never a URL from article text.
Provider/model mapping is an adapter responsibility. For BYOK held in the gateway,
use the gateway authentication token; when keys are held locally, use the documented
provider Authorization header plus `cf-aig-authorization`. Distinguish these modes
explicitly at setup and fail on missing credentials; never infer success from HTTP
200 without parsing the response. Do not forward secrets across redirects.

Store neither tokens nor raw request headers in sidecars/logs. Disable gateway
request-body logging for private drafts unless the operator deliberately enables
it with a retention policy. Credentialed jobs use trusted configuration. Article
instructions are quoted data, not system prompts or tool commands. No tool use,
filesystem access, URL retrieval or shell execution is granted to the model.

## Prompts and evaluation

Embed versioned `prompts/summary-ja-v1.txt` and `summary-en-v1.txt` in the tool.
The checked-in prompt specifications define the initial contract. They prohibit invented facts,
clickbait and judgments not in the article, and preserve names/technical terms.

`tests/ai/summary-corpus.yaml` covers short/long Japanese technical content, an
essay, English technical and announcement content, and a bilingual pair. For each
candidate, keep the same prompt and input, record parameters/usage/latency/cost
where available, and save an anonymized A/B/C review bundle. Keep the label-to-model
mapping in a separate file hidden from reviewers until scoring is complete.

Deterministic checks: format, length, empty/refusal output, proper-noun preservation
where annotated, and no unsupported links. Human scores (1–5): faithfulness,
important-point coverage, Japanese/English naturalness, terminology, concision,
absence of clickbait. Any fabricated material fact rejects a candidate regardless
of average score. Include regression comparisons before a model/prompt change.
The sample corpus is not itself evidence of real model quality.
